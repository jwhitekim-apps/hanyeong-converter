# 한영타 변환기 v3.0 (진단 로그 포함)

## 설치
1. 압축 풀기.
2. 크롬 주소창에 `chrome://extensions` → 이동.
3. 우측 상단 **개발자 모드** 켜기.
4. **압축해제된 확장 프로그램을 로드** → manifest.json 들어있는 **ext 폴더** 선택.
5. **테스트할 웹페이지를 새로고침**(설치 전 열려있던 탭엔 코드가 안 들어감).

## 사용
- 텍스트 드래그 → **우클릭 → "한영타 변환"**
- 또는 드래그 → **Option(⌥) + Shift + Z**

## 진단 방법 (이게 핵심)
이 버전은 콘솔에 전 과정을 로그로 찍습니다. 어디서 끊기는지 바로 보입니다.

### A. content script가 주입됐는지
1. 테스트 페이지(예: google.com)에서 **⌥⌘I** → **Console** 탭.
2. 페이지 새로고침.
3. `[한영타-CS] content script 로드됨 v3.0.0 @ ...` 가 보이면 → 주입 성공.
   안 보이면 → 그 페이지에 주입이 안 된 것(매칭/새로고침 문제).

### B. 우클릭 메뉴 / 변환 흐름
- 드래그 후 우클릭 → 콘솔에 `run() 시작`, `... 경로`, `→ 변환결과` 가 찍힘.
- background 쪽 로그는 `chrome://extensions` → 카드의 **"서비스 워커"** 클릭 → 그 콘솔에
  `메뉴 생성 성공`, `메뉴 클릭됨`, `content 응답` 이 찍힘.

### 보이는 로그를 복사해서 알려주면 원인 즉시 특정 가능.

## 동작 범위
- 일반 input/textarea, contenteditable(클로드/네이버 등 대부분): 그 자리 교체.
- 편집 불가한 일반 텍스트: 변환 결과를 **클립보드로 복사**.
